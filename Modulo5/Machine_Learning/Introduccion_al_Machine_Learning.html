■ 1. Introducción al Machine Learning

¿Qué es el Machine Learning?

Es la rama de la Inteligencia Artificial que permite a un sistema aprender patrones a partir de datos, en lugar de seguir reglas escritas explícitamente por una persona.

En otras palabras: en lugar de programar la lógica paso a paso, le mostramos ejemplos al modelo y él encuentra la relación entre ellos.

Programación tradicional
Datos + Reglas → Resultados
La persona programadora define cada regla de forma manual.
Machine Learning
Datos + Resultados → Reglas (modelo)
El algoritmo descubre el patrón a partir de ejemplos.
Ejemplo para fijar la idea: para detectar correo spam de forma tradicional habría que escribir reglas como "si contiene la palabra 'gratis' y tiene un enlace, marcar como spam". En ML, se le muestran miles de correos ya etiquetados como spam o no spam, y el algoritmo aprende por sí mismo qué combinaciones de palabras, remitentes y estructura son indicio de spam — incluso patrones que una persona no habría anticipado.

¿Por qué Machine Learning hoy?

El ML no es una idea nueva —sus bases matemáticas datan de décadas atrás— pero solo se volvió práctico y masivo en los últimos años gracias a tres factores que convergieron:

Más datos

Empresas y dispositivos generan volúmenes de datos sin precedentes.

Más cómputo

GPUs y la nube permiten entrenar modelos complejos rápidamente.

Mejores algoritmos

Avances en técnicas estadísticas y de aprendizaje profundo.

Aplicaciones cotidianas

  • Recomendaciones (Netflix, Spotify, e-commerce)
  • Detección de fraude en tarjetas y transacciones
  • Filtros de spam en el correo electrónico
  • Diagnóstico asistido en imágenes médicas
  • Mantenimiento predictivo en maquinaria industrial
  • Predicción de demanda y precios

Clasificación vs. regresión (dentro de supervisado): la clasificación predice una categoría discreta (¿es spam o no?, ¿el cliente se va o se queda?), mientras que la regresión predice un valor numérico continuo (¿cuánto costará la casa?, ¿cuántas unidades se venderán el próximo mes?).

Ejemplo aplicado — Aprendizaje no supervisado

Aquí no hay una columna "respuesta correcta": el modelo recibe puntos de datos sin etiqueta y debe encontrar por sí mismo la estructura que los agrupa.

Segmentación de clientes de una tienda: se parte de un conjunto de puntos "sin agrupar" (por ejemplo, frecuencia de compra vs. monto gastado). El algoritmo de clustering descubre, sin que nadie le diga cuántos grupos buscar, dos comportamientos distintos: Grupo A — clientes frecuentes de bajo gasto y Grupo B — clientes ocasionales de alto gasto. Ese hallazgo es el resultado del modelo, no un dato que ya existiera en la tabla original.
■ 3. Flujo de un proyecto de ML

Las etapas de un proyecto de Machine Learning

Todo proyecto de ML —independientemente de su complejidad— sigue un ciclo similar. Entender estas etapas ayuda a planificar el trabajo y a saber en qué punto puede fallar un proyecto.

1. Definir el problema
→
2. Recolectar datos
→
3. Preparar y limpiar
→
4. Dividir los datos
→
5. Entrenar el modelo
→
6. Evaluar resultados
→
7. Desplegar y monitorear

1. Definir el problema

¿Qué se quiere predecir o descubrir? ¿Es un problema de clasificación, regresión o clustering? Sin esta claridad, ninguna técnica funciona bien.

2. Recolectar datos

Reunir la información histórica relevante: transacciones, encuestas, sensores, bases de datos internas, etc.

3. Preparar y limpiar

Eliminar duplicados, tratar valores faltantes, corregir errores y transformar los datos a un formato utilizable por el algoritmo.

4. Dividir los datos

Separar el conjunto en datos de entrenamiento (train) y de prueba (test) — típicamente 70/30 u 80/20 — para poder evaluar el modelo con casos que nunca vio durante el entrenamiento.

5. Entrenar el modelo

Elegir un algoritmo (regresión, árboles de decisión, redes neuronales, etc.) y ajustarlo usando únicamente los datos de entrenamiento.

6. Evaluar resultados

Medir qué tan bien predice el modelo con los datos de prueba, usando métricas como exactitud (accuracy), precisión, recall o error, según el tipo de problema.

7. Desplegar y monitorear

Poner el modelo en producción y vigilar su desempeño en el tiempo, ya que los patrones de los datos pueden cambiar (esto se conoce como drift).

¿Por qué dividir los datos en train/test? Si evaluamos el modelo con los mismos datos que usamos para entrenarlo, corremos el riesgo de sobreajuste (overfitting): el modelo "memoriza" los ejemplos en vez de aprender el patrón general, y luego falla con datos nuevos. Reservar una porción de prueba —que el modelo nunca vio— simula cómo se comportará en la vida real.
■ 4. Variables, features y target

Qué predice el modelo y con qué información

Antes de entrenar cualquier modelo supervisado, hay que distinguir claramente dos tipos de variables dentro del conjunto de datos:

Features (variables predictoras)
Son las variables de entrada: la información que el modelo usa para hacer su predicción.
Ejemplo: edad, ingreso mensual, historial de pagos, número de créditos activos.
Target (variable objetivo)
Es lo que el modelo intenta predecir: el resultado o respuesta.
Ejemplo: "pagó el préstamo" / "no lo pagó".
En una tabla de datos: cada fila suele representar una observación (una persona, una transacción, un producto) y cada columna una variable. Todas las columnas excepto una son features; la columna restante —la que se quiere predecir— es el target. Elegir bien qué features incluir (y descartar las irrelevantes o redundantes) es una de las tareas más determinantes en la calidad final del modelo.
■ Herramientas de trabajo

Con qué vamos a trabajar en la práctica

Para la parte práctica de esta unidad usaremos un conjunto pequeño pero suficiente de herramientas, todas de uso libre y muy extendidas en la industria:

Python

Lenguaje de programación principal para ciencia de datos y ML.

Pandas

Librería para cargar, explorar y limpiar datos en tablas.

Scikit-learn

Librería con los algoritmos de clasificación y clustering que usaremos.

Google Colab

Entorno donde escribimos y ejecutamos el código, sin instalar nada.

Por qué esta combinación: Pandas se encarga de la parte de datos (leer un CSV, filtrar filas, revisar valores faltantes), Scikit-learn se encarga de la parte de modelo (dividir train/test, entrenar, predecir, evaluar) y Colab elimina la fricción de instalar Python y librerías localmente, ya que corre en la nube desde el navegador.
■ Práctica guiada

Actividad 1 · Clasificación supervisada

Vamos a construir, paso a paso, un modelo que predice si un cliente comprará o no un producto, aplicando en código el flujo de la sección 3.

1

Cargar y explorar los datos

Leer el dataset y revisar sus columnas, tipos de datos y valores faltantes.

2

Definir features y target

Elegir qué columnas son predictoras (X) y cuál es la variable a predecir (y).

3

Dividir train / test

Separar los datos en un conjunto para entrenar y otro para evaluar (ej. 80/20).

4

Entrenar el modelo

Ajustar un modelo de clasificación (ej. Árbol de Decisión) con los datos de entrenamiento.

5

Evaluar el modelo

Medir la exactitud (accuracy) y revisar la matriz de confusión con los datos de prueba.

6

Predecir casos nuevos

Usar el modelo entrenado para predecir clientes que aún no conocemos.

Nota sobre el paso 5: la matriz de confusión muestra, además del porcentaje de aciertos, en qué se está equivocando el modelo — por ejemplo, cuántos clientes que sí iban a comprar fueron clasificados erróneamente como "no compra" (falso negativo) y viceversa (falso positivo). Esa información suele ser tan importante como el accuracy general, sobre todo cuando el costo de cada tipo de error es distinto.
