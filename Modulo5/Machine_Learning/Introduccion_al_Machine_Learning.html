■ 1. Introducción al Machine Learning

¿Qué es el Machine Learning?

Es la rama de la Inteligencia Artificial que permite a un sistema aprender patrones a partir de datos, en lugar de seguir reglas escritas explícitamente por una persona.

En otras palabras: en lugar de programar la lógica paso a paso, le mostramos ejemplos al modelo y él encuentra la relación entre ellos.

Programación tradicional
Datos + Reglas → Resultados
La persona programadora define cada regla de forma manual.
Machine Learning
Datos + Resultados → Reglas (modelo)
El algoritmo descubre el patrón a partir de ejemplos.
Ejemplo para fijar la idea: para detectar correo spam de forma tradicional habría que escribir reglas como "si contiene la palabra 'gratis' y tiene un enlace, marcar como spam". En ML, se le muestran miles de correos ya etiquetados como spam o no spam, y el algoritmo aprende por sí mismo qué combinaciones de palabras, remitentes y estructura son indicio de spam — incluso patrones que una persona no habría anticipado.

¿Por qué Machine Learning hoy?

El ML no es una idea nueva —sus bases matemáticas datan de décadas atrás— pero solo se volvió práctico y masivo en los últimos años gracias a tres factores que convergieron:

Más datos

Empresas y dispositivos generan volúmenes de datos sin precedentes.

Más cómputo

GPUs y la nube permiten entrenar modelos complejos rápidamente.

Mejores algoritmos

Avances en técnicas estadísticas y de aprendizaje profundo.

Aplicaciones cotidianas

  • Recomendaciones (Netflix, Spotify, e-commerce)
  • Detección de fraude en tarjetas y transacciones
  • Filtros de spam en el correo electrónico
  • Diagnóstico asistido en imágenes médicas
  • Mantenimiento predictivo en maquinaria industrial
  • Predicción de demanda y precios

Ejemplo aplicado — Aprendizaje no supervisado

Aquí no hay una columna "respuesta correcta": el modelo recibe puntos de datos sin etiqueta y debe encontrar por sí mismo la estructura que los agrupa.

Segmentación de clientes de una tienda: se parte de un conjunto de puntos "sin agrupar" (por ejemplo, frecuencia de compra vs. monto gastado). El algoritmo de clustering descubre, sin que nadie le diga cuántos grupos buscar, dos comportamientos distintos: Grupo A — clientes frecuentes de bajo gasto y Grupo B — clientes ocasionales de alto gasto. Ese hallazgo es el resultado del modelo, no un dato que ya existiera en la tabla original.
Dos tareas dentro de lo no supervisado: el clustering agrupa elementos parecidos entre sí (por ejemplo, segmentar clientes según sus hábitos de compra), mientras que la reducción de dimensión resume muchas variables en pocas, conservando lo esencial — útil para simplificar cientos de variables y poder visualizarlas o acelerar el análisis posterior.

Las etapas de un proyecto de Machine Learning

Todo proyecto de ML —independientemente de su complejidad— sigue un ciclo similar. Entender estas etapas ayuda a planificar el trabajo y a saber en qué punto puede fallar un proyecto.

4. Dividir los datos
→
5. Entrenar el modelo
→

→
7. Desplegar y monitorear

1. Definir el problema

¿Qué se quiere predecir o descubrir? ¿Qué decisión de negocio apoya? ¿Es un problema de clasificación, regresión o clustering? Sin esta claridad, ninguna técnica funciona bien.

2. Recolectar datos

Reunir la información histórica relevante para el problema: transacciones, encuestas, sensores, bases de datos internas, etc.

3. Preparar y limpiar

Corregir errores, datos faltantes y formatos inconsistentes; eliminar duplicados y transformar los datos a un formato utilizable por el algoritmo.

4. Dividir los datos

Separar el conjunto en datos de entrenamiento (train) y de prueba (test) — típicamente 70/30 u 80/20 — para poder evaluar el modelo con casos que nunca vio durante el entrenamiento.

5. Entrenar el modelo

Elegir un algoritmo (regresión, árboles de decisión, redes neuronales, etc.) y ajustarlo: el algoritmo aprende el patrón a partir del conjunto de entrenamiento.

6. Evaluar resultados

Medir el desempeño del modelo con el conjunto de prueba, usando métricas como exactitud (accuracy), precisión, recall o error, según el tipo de problema.

7. Desplegar y monitorear

Poner el modelo en producción y vigilar su desempeño en el tiempo, ya que los patrones de los datos pueden cambiar (esto se conoce como drift).

¿Por qué dividir los datos en train/test? Si evaluamos el modelo con los mismos datos que usamos para entrenarlo, corremos el riesgo de sobreajuste (overfitting): el modelo "memoriza" los ejemplos en vez de aprender el patrón general, y luego falla con datos nuevos. Reservar una porción de prueba —que el modelo nunca vio— simula cómo se comportará en la vida real.
■ 4. Variables, features y target

Qué predice el modelo y con qué información

Antes de entrenar cualquier modelo supervisado, hay que distinguir claramente los tipos de variables dentro del conjunto de datos. Todo parte de la idea más general de variable: cualquier característica medible de un dato (edad, precio, color, ciudad, etc.). A partir de ahí, dentro de un problema supervisado esas variables se dividen en dos roles distintos:

Features (variables predictoras)
Son las variables de entrada: la información que el modelo usa como "pistas" para hacer su predicción.
Ejemplo: edad, ingreso mensual, antigüedad, historial de pagos, número de créditos activos.
Target (variable objetivo)
Es lo que el modelo intenta predecir: la "respuesta" del modelo.
Ejemplo: "pagó el préstamo" / "no lo pagó".

Ejemplo — dataset de clientes

EdadIngresoAntigüedad¿Compra?
25$8001 añoNo
41$1,5005 añosSí
36$1,1003 añosSí
En esta tabla, Edad, Ingreso y Antigüedad son las features; ¿Compra? es el target. Cada fila suele representar una observación (una persona, una transacción, un producto) y cada columna una variable. Todas las columnas excepto una son features; la columna restante —la que se quiere predecir— es el target. Elegir bien qué features incluir (y descartar las irrelevantes o redundantes) es una de las tareas más determinantes en la calidad final del modelo.
¿Y en un problema no supervisado? Ahí no existe target: no hay una columna "respuesta correcta" que el modelo deba predecir. Solo se trabaja con features, y el algoritmo las usa para descubrir por sí mismo estructura, agrupaciones o patrones en los datos — como vimos en el ejemplo de segmentación de clientes.

4

Predecir casos nuevos

Usar el modelo entrenado para predecir clientes que aún no conocemos.

Nota sobre el paso 5: la matriz de confusión muestra, además del porcentaje de aciertos, en qué se está equivocando el modelo — por ejemplo, cuántos clientes que sí iban a comprar fueron clasificados erróneamente como "no compra" (falso negativo) y viceversa (falso positivo). Esa información suele ser tan importante como el accuracy general, sobre todo cuando el costo de cada tipo de error es distinto.
■ Práctica guiada

Actividad 2 · Clustering no supervisado

Vamos a segmentar clientes en grupos según su comportamiento, sin decirle al modelo cuáles son los grupos: aquí no hay target, solo features.

1

Cargar los datos

Leer el dataset de clientes (sin ninguna columna de "respuesta").

2

Escalar las variables

Normalizar los datos para que ninguna variable domine por su magnitud (ej. que el ingreso en dólares no "aplaste" a la frecuencia de compra).

3

Elegir el número de grupos (k)

Usar el método del codo para decidir cuántos clústeres formar antes de entrenar el algoritmo.

4

Aplicar K-Means

Entrenar el algoritmo para que agrupe a los clientes similares entre sí, según las features escaladas.

5

Visualizar los grupos

Graficar los clústeres para ver cómo se distribuyen los clientes en el espacio de variables.

6

Interpretar cada grupo

Describir el perfil de cada clúster (ej. "alto gasto, baja frecuencia") para convertir el resultado técnico en una conclusión de negocio.

¿Por qué escalar antes de aplicar K-Means (paso 2)? K-Means agrupa según la distancia entre puntos. Si una variable se mide en dólares (ej. ingreso, de 0 a 5,000) y otra en unidades pequeñas (ej. frecuencia de compra, de 0 a 20), la variable con números más grandes dominará el cálculo de distancia aunque no sea más importante. Escalar (por ejemplo, llevando todas las variables a un rango comparable) evita ese sesgo.
¿Por qué elegir k antes de entrenar (paso 3)? A diferencia de un modelo supervisado, K-Means no "sabe" cuántos grupos existen — hay que indicárselo. El método del codo consiste en probar distintos valores de k y graficar qué tan compactos quedan los grupos en cada caso; el punto donde la mejora deja de ser significativa (el "codo" de la curva) suele ser una buena elección de k.

■ 1. Concepto de modelo predictivo

¿Qué es un modelo predictivo?

Un modelo predictivo es, en el fondo, un adivino entrenado con ejemplos: le mostramos casos pasados donde ya sabemos qué pasó, y aprende un patrón para adivinar qué pasará en casos nuevos.

En simple: imagina un médico con muchos años de experiencia — ha visto tantos casos que, con solo un par de síntomas, ya intuye el diagnóstico. El modelo hace lo mismo, pero con números.

Sin modelo predictivo
Reglas fijas, escritas a mano.
Cada caso se decide con reglas que una persona programó, una por una.
Con modelo predictivo
Ejemplos → Patrón → Predicción
El modelo descubre el patrón solo, a partir de ejemplos ya resueltos.

¿Cómo "aprende" un modelo predictivo?

1

Observa ejemplos

Revisa muchos casos pasados junto con su resultado real.

2

Encuentra el patrón

Detecta qué combinación de datos suele llevar a cada resultado.

3

Predice casos nuevos

Aplica el patrón aprendido a datos que nunca había visto.

Aplicaciones cotidianas

  • Recomendaciones de series o música
  • Predicción del clima
  • Aprobación de créditos bancarios
  • Precio estimado de una casa
  • Diagnóstico médico asistido
  • Predicción de ventas del próximo mes

Una predicción no es una certeza

Un modelo predictivo no tiene una bola de cristal: entrega una estimación basada en patrones pasados, casi siempre expresada como una probabilidad, no como un sí o un no absoluto.

En simple: cuando el pronóstico dice "80% de probabilidad de lluvia", no significa que vaya a llover el 80% del día — significa que, en situaciones parecidas, llovió 8 de cada 10 veces.

Probabilidad de cancelar72%
Probabilidad de NO cancelar28%
El modelo no dice "cancela" o "no cancela": entrega estos dos porcentajes, y nosotros decidimos a partir de qué probabilidad actuamos. Por eso ninguna predicción se toma como verdad absoluta: siempre conviene medir qué tan seguido acierta el modelo — algo que se conoce como evaluar el modelo (accuracy, precisión, recall) y que ya vimos en la Actividad 1.

Un servicio de streaming quiere anticiparse a las cancelaciones. Junta el historial de miles de clientes: cuántos meses llevan activos, cuántas quejas han hecho, y si finalmente cancelaron o no.

En simple: es como notar que los clientes que se quejan seguido y llevan pocos meses son justamente los que más se van — el modelo detecta esa señal sin que se la digamos explícitamente. El cliente nuevo (2 meses, 3 quejas) se parece mucho más a los casos "Sí" de la tabla (pocos meses, muchas quejas) que a los casos "No" (muchos meses, pocas quejas).

■ 2. Variables independientes y dependientes

La pista (X) y la respuesta (Y)

Ya vimos esta idea como features y target en la sección 4; aquí es la misma distinción vista desde la notación matemática que usan los algoritmos: cada variable predictora se llama independiente y se agrupa bajo la letra X, y la variable que queremos adivinar se llama dependiente y se representa con Y.

X Variable(s) independiente(s)
La "pista": información que ya conocemos y que el modelo usa como entrada. Puede haber varias X a la vez (X₁, X₂, X₃…).
No depende de ninguna otra variable del problema — la aportamos nosotros.
Y Variable dependiente
La "respuesta": lo que queremos adivinar. Su valor depende de X — por eso el modelo busca la función Y = f(X).
Solo puede haber una Y por modelo.
Retomando el ejemplo del streaming: X = meses activo y número de quejas (las pistas que observamos de cada cliente); Y = ¿canceló? (la respuesta que el modelo intenta adivinar). El modelo busca la relación Y = f(X) que mejor explica, con los datos históricos, cómo esas dos pistas se conectan con el resultado.

Ejemplo — dataset de casas

m²Habs.Precio

Variables independientes (X): metros cuadrados, habitaciones. Variable dependiente (Y): precio. En simple: si quieres adivinar el precio de una casa (Y), sus metros cuadrados y su ubicación son las pistas (X).

Cuidado con lo que pones en X

Un mismo dato puede ser X en un problema y Y en otro. El precio de la casa es Y cuando queremos calcularlo, pero puede ser X cuando queremos predecir si un comprador la va a visitar. En simple: X e Y no son etiquetas fijas de una columna — dependen de la pregunta que estés haciendo en ese momento.

Hay otro cuidado todavía más importante: no incluir en X información que, en la práctica, no existiría todavía al momento de predecir.

Error común
Usar información "del futuro". Predecir cancelación usando como X "recibió correo de despedida" — ese dato solo existe después de que el cliente ya canceló.
Buena práctica
Usar solo lo que ya se sabe. Usar meses activo y número de quejas — datos que sí existen antes de que el cliente decida cancelar o no.

Un matiz importante: correlación no es causa

Que X y Y estén relacionadas estadísticamente no significa que X provoque Y. En el ejemplo, las quejas no "causan" la cancelación por sí solas — probablemente ambas son síntoma de una insatisfacción de fondo. El modelo detecta el patrón útil para predecir, no necesariamente la razón profunda detrás de él; esa interpretación de negocio sigue siendo tarea de la persona analista.

■ 3. Introducción a algoritmos básicos

Los 3 "cerebros" más simples

Existen decenas de algoritmos de aprendizaje supervisado, pero casi todos los cursos introductorios arrancan con estos tres porque son fáciles de visualizar y ya resuelven una buena parte de los problemas reales.

Regresión lineal

Traza la línea (o el plano) que mejor se ajusta a los datos, y la usa para predecir un valor numérico continuo.

Y = m·X + b

Árbol de decisión

Hace una serie de preguntas de sí/no en cadena hasta llegar a una predicción, como un diagrama de flujo.

¿Ingreso > $1,000? → …

KNN (k vecinos más cercanos)

Busca los "k" casos históricos más parecidos al caso nuevo y predice por mayoría (o promedio) entre ellos.

"Dime con quién andas…"

Regresión lineal, en simple

Busca la recta Y = m·X + b que mejor "atraviesa" la nube de puntos. Por ejemplo, con el tamaño de una casa (X) y su precio de venta (Y) en decenas de casas vendidas, la regresión encuentra la pendiente m (cuánto sube el precio por cada m² extra) y el punto de partida b. Con esa recta, una casa nueva de 90 m² se ubica en la recta y se lee su precio estimado — sin necesidad de haberla visto antes.

Árbol de decisión, en simple

Funciona como un diagrama de flujo de preguntas: "¿el ingreso mensual es mayor a $1,000?" → si no, rechazar el crédito; si sí, siguiente pregunta: "¿la antigüedad laboral es mayor a 2 años?" → según la respuesta, aprobar o seguir preguntando. Cada pregunta divide el grupo de datos en dos ramas más "puras" (más parecidas entre sí), hasta llegar a una hoja final con la predicción.

KNN, en simple

Para un cliente nuevo, el algoritmo busca en los datos históricos a sus k clientes más parecidos (por ejemplo, k = 3) según las features (edad, ingreso, etc.) y mira qué hicieron ellos. Si 2 de esos 3 "vecinos" compraron y 1 no, KNN predice que el cliente nuevo también comprará — es literalmente la idea de "dime con quién andas y te diré quién eres", convertida en algoritmo.

7 horas de estudio → 82 puntos estimados
En simple: los puntos casi forman una línea recta — el modelo solo tiene que encontrar esa línea. La predicción coincide con el dato real de la tabla — señal de que el modelo aprendió bien el patrón.

■ 4. Preparación de datos para modelado

Por qué hay que "lavar y picar" los datos antes de cocinar el modelo

Ningún algoritmo —por bueno que sea— produce buenas predicciones si se le alimenta con datos sucios o mal preparados. En la práctica, esta etapa suele tomar más tiempo que el entrenamiento del modelo en sí.

Valores faltantes

Completar (con promedio, mediana, etc.) o eliminar filas/columnas con datos vacíos.

Duplicados y errores

Eliminar filas repetidas y corregir valores imposibles (ej. edad = -5 o 300).

Codificar categorías

Convertir texto (ej. "Sí"/"No", ciudades) en números que el algoritmo pueda procesar.

Escalar variables

Llevar las variables numéricas a rangos comparables, clave para KNN y K-Means.

La metáfora de la cocina: "lavar" los datos es limpiar lo que está sucio o incompleto (valores faltantes, duplicados, errores de captura); "picar" es darles el formato exacto que el algoritmo necesita para "cocinarlos" (convertir texto a números, escalar, dividir en train/test). Saltarse este paso es como intentar cocinar con verduras sin lavar y sin cortar: el resultado —el modelo— sale de mala calidad, sin importar qué tan bueno sea el algoritmo elegido.
Conexión con lo ya visto: esta etapa corresponde al paso 3 ("Preparar y limpiar") del flujo de un proyecto de ML visto antes, y es la razón por la que, en la Actividad 2, escalamos las variables antes de aplicar K-Means — un dato mal preparado puede arruinar incluso al mejor algoritmo.

¿Por qué separar entrenamiento y prueba?

Evaluar un modelo con los mismos datos que usó para aprender es como calificar un examen con las mismas preguntas que el estudiante ya había practicado con las respuestas incluidas: parecería perfecto, pero no sabemos si realmente entendió.

Se usa solo para medir qué tan bien predice — nunca para entrenar.

En simple: nunca le hagas la prueba final a alguien con las mismas preguntas que ya practicó — necesitas preguntas nuevas para saber si realmente aprendió.

■ 1. Regresión lineal

Una línea que resume la tendencia

Piensa en un taxi: pagas un monto fijo al subir (el banderazo) y luego un precio por cada kilómetro. Si sabes cuántos kilómetros vas a recorrer, puedes estimar cuánto pagarás.

tarifa = banderazo + precio por kilómetro × kilómetros

Eso ya es un modelo de regresión lineal: una variable de entrada, una salida numérica y una relación en línea recta.

La fórmula, parte por parte

valor estimado = punto de partida + pendiente × dato conocido

Valor estimado

Lo que queremos predecir. En el taxi: la tarifa.

Punto de partida

El resultado cuando el dato conocido vale cero. En el taxi: el banderazo.

Pendiente

Cuánto cambia el resultado por cada unidad extra. En el taxi: el precio por kilómetro.

Dato conocido

La información que sí tenemos. En el taxi: los kilómetros.

En palabras simples: toda regresión lineal tiene esta forma. La computadora no inventa la fórmula: solo busca los dos números, el punto de partida y la pendiente, que mejor se ajustan a los datos. Es la misma idea que Y = m·X + b vista en la Unidad 2 — aquí le damos nombre a cada parte.

¿Cómo encuentra la mejor línea?

1. Traza una línea candidata
→
2. Mide el residuo de cada punto
→
3. Eleva cada residuo al cuadrado y suma
→
4. Elige la línea con la suma más pequeña
Mínimos cuadrados: el residuo es la distancia vertical de cada punto real a la línea — el error de esa predicción. Ninguna línea pasa por todos los puntos, así que siempre hay errores. Se elevan al cuadrado para que los errores positivos y negativos no se cancelen entre sí y para que los errores grandes pesen más; la mejor línea es la que, al sumar todos esos cuadrados, se equivoca menos en conjunto.

Regresión múltiple: más de una pista

La misma idea, pero con varias X a la vez: cada feature aporta su propio coeficiente.

precio = punto de partida + efecto por m² × m² + efecto por habitación × habitaciones + efecto por año × antigüedad
VariableCoeficienteCómo se lee
Metros cuadrados+1,200Cada m² extra suma unos $1,200 al precio
Habitaciones+8,000Cada habitación extra suma unos $8,000
Antigüedad (años)−1,500Cada año de antigüedad resta unos $1,500
Cada coeficiente dice cuánto cambia el precio si esa característica aumenta en 1 y las demás se quedan igual. El signo indica si sube o baja. Valores ilustrativos.

■ 2. Clasificación

Clasificar es asignar una etiqueta

Predecir a qué grupo o categoría pertenece cada caso. Por ejemplo, decidir si un correo es spam o si un cliente volverá.

Un correo

Entrada. Etiqueta: Spam · No spam

Un estudiante

Entrada. Etiqueta: Aprueba · Reprueba

Una transacción

Entrada. Etiqueta: Normal · Fraude

En palabras simples: el modelo aprende de ejemplos que ya tienen su etiqueta, como correos que alguien marcó como spam. Así descubre las señales que distinguen a cada grupo y luego etiqueta casos nuevos.

Binaria o multiclase

Binaria
Dos opciones posibles, normalmente codificadas como 1 y 0.
sí / no · 1 / 0 — spam, fraude, aprobación de crédito
Multiclase
Tres o más opciones; el modelo elige una de ellas.
bajo / medio / alto — especie de flor, nivel de riesgo, tipo de cliente
En palabras simples: muchos clasificadores primero calculan una probabilidad para cada opción, por ejemplo 87% spam, y después eligen la opción más probable. Binaria o multiclase, la idea es la misma.
■ 3. Algoritmos básicos de clasificación

Regresión logística y árboles de decisión

Dos formas de llegar a una categoría: con porcentajes o con preguntas en cadena.

Algoritmo 1 · Regresión logística

A pesar de su nombre, se usa para clasificar, no para predecir números. Combina las variables como una regresión lineal y pasa el resultado por la función sigmoide, que lo comprime entre 0 y 1.

probabilidad = curva S ( punto de partida + pendiente × horas de estudio )
La curva tiene forma de S porque una probabilidad nunca baja de 0% ni pasa de 100%. Una recta no serviría aquí — daría probabilidades negativas o mayores a 1.

Del porcentaje a la decisión: el umbral

Horas de estudioProbabilidad de aprobarDecisión (umbral 0.5)
20.05Reprueba
40.27Reprueba
60.73Aprueba
80.95Aprueba
El modelo da un porcentaje, pero al final necesitamos un sí o un no. El umbral es la línea de corte: por encima del 50% decimos "aprueba", por debajo, "reprueba". Si bajamos el umbral, el modelo marca más casos como positivos — detecta más, pero también se equivoca más. En fraude o salud suele convenir un umbral más bajo para no dejar pasar casos.

Algoritmo 2 · Árbol de decisión

Se sigue el camino desde arriba: cada respuesta lleva a otra pregunta, hasta llegar a una hoja con la decisión.

P1
¿Ingreso mensual mayor a $1,000?
No → Rechazar crédito  ·  Sí → siguiente pregunta
P2
¿Tiene deudas atrasadas?
Sí → Rechazar crédito  ·  No → Aprobar crédito
Cada pregunta divide los datos en grupos más parecidos entre sí. Las hojas —las cajas finales— contienen la predicción. Es como el juego de las 20 preguntas: el algoritmo elige, en cada paso, la pregunta que mejor separa los datos.

Hiperparámetros: controlar el tamaño del árbol

Profundidad máxima

Cuántas preguntas seguidas puede hacer. Poca profundidad da un modelo simple; mucha lo hace memorizar.

Mínimo de casos por hoja

Cuántos ejemplos debe tener como mínimo cada respuesta final. Evita reglas basadas en uno o dos casos raros.

Forma de medir cada pregunta

El cálculo que usa el algoritmo para elegir la pregunta que mejor separa los grupos.

En palabras simples: estos límites los decide la persona antes de entrenar, no el modelo. Un buen punto de partida es una profundidad de 3 preguntas; luego se revisa con los datos de prueba si conviene más o menos. Un árbol sin límite puede crecer hasta tener una hoja por cada ejemplo: acierta el 100% en entrenamiento y falla con datos nuevos — el mismo sobreajuste que vimos en la Unidad 2.

■ 4. Interpretación de resultados

Un modelo solo es útil si sabemos cuánto se equivoca

Predecir es fácil; saber si podemos confiar en la predicción es el trabajo real. Por eso se dedica tanto tiempo a leer métricas, coeficientes y errores antes de tomar una decisión con un modelo.

Regresión: ¿qué tan lejos quedamos?

Error promedio (MAE)

En promedio, cuánto nos equivocamos, en las mismas unidades de lo que predecimos. Ej.: error de 12 → fallamos por 12 unidades.

Error con castigo (RMSE)

Parecido al error promedio, pero pesa más los errores grandes. Si es mucho mayor que el MAE, hay errores grandes sueltos.

Porcentaje explicado (R²)

Qué parte de los cambios en el resultado logra explicar el modelo. 1 = perfecto · 0 = igual que adivinar el promedio.

En palabras simples: las tres se calculan con datos de prueba y se leen juntas — ninguna basta por sí sola. MAE y RMSE se interpretan en las unidades del problema (colones, grados, kWh); R² se interpreta como qué tan cerca está de 1.

Cómo leer los coeficientes

Signo
Positivo: cuando el dato de entrada sube, la predicción sube. Negativo: baja.
tarifa = 2.5 + 0.8 × km → cada km extra suma 0.8 a la tarifa. Ejemplo: 10 km cuesta 2.5 + 0.8×10 = 10.5
Tamaño
Depende de las unidades; compara coeficientes solo si los datos están en la misma escala.
En logística, un coeficiente positivo aumenta la probabilidad de la respuesta "sí".
Asociación, no causa: un coeficiente describe una relación en los datos; por sí solo no prueba que una cosa cause la otra — el mismo matiz que vimos con "correlación no es causa" en la Unidad 2.

Clasificación: la matriz de confusión

Ejemplo: filtro de spam.

Real: spam · Predicho: spam

Verdadero positivo

Era spam y el modelo lo detectó.

Real: spam · Predicho: no spam

Falso negativo

Era spam y se le escapó.

Real: no spam · Predicho: spam

Falso positivo

Correo legítimo enviado a spam.

En palabras simples: los aciertos son verdadero positivo y verdadero negativo. Los dos errores no pesan igual: perder un correo importante en spam (falso positivo) suele molestar más que recibir un spam de vez en cuando (falso negativo) — o al revés, según el problema.

Exactitud del modelo "siempre normal"99%

Un modelo puede tener un número alto y aun así no servir: siempre pregunta si acierta en los casos que de verdad importan.
