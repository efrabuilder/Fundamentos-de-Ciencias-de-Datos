1. Principios de diseño visual y estratégico

Cómo ordenar, colorear y titular un dashboard para que guíe la atención del usuario.

Jerarquía visual estratégica

El ojo occidental lee en patrón de «F» o «Z». Coloca los KPIs más críticos y los filtros globales en la esquina superior izquierda. Usa el centro para las tendencias principales y deja la parte inferior exclusivamente para las tablas de datos granulares.

Métricas con contexto inmediato

Un KPI aislado como «150 ventas» no aporta valor operativo. Cada métrica principal debe incluir una comparativa clara: porcentaje de crecimiento frente al mes anterior, año contra año o desviación respecto a la meta del negocio.

Uso intencional del color

El color debe guiar la atención, no decorar. Utiliza paletas neutras (grises, azules apagados) para la estructura base y reserva los colores semánticos (rojo, verde, amarillo) únicamente para resaltar alertas, anomalías o el cumplimiento de objetivos.

Títulos narrativos

Reemplaza las descripciones estáticas como «Ventas por Región» por conclusiones directas como «Norteamérica concentró el 45% de las ventas en Q3». El título debe entregar la respuesta de negocio antes de que el usuario analice los ejes del gráfico.

Norteamérica concentró el 45% de las ventas en Q3

Aprovechamiento de tooltips y desaturación

Evita saturar el lienzo con múltiples etiquetas de datos superpuestas. Oculta la información secundaria y los desgloses granulares dentro de ventanas flotantes (tooltips) que solo aparezcan cuando el usuario interactúa con un punto de interés.

2. Buenas prácticas de desarrollo en Power BI

Decisiones técnicas que mantienen el reporte rápido, liviano y fácil de usar.

Modelado en estrella (Star Schema) innegociable

Power BI está diseñado específicamente para trabajar con tablas de hechos (datos cuantitativos) y dimensiones (catálogos). El modelo de datos debe estructurarse correctamente antes de crear el primer gráfico; mantener todo en una sola tabla plana (tipo Excel) destruye el rendimiento del motor VertiPaq y complica innecesariamente los cálculos en DAX.

Medidas (Measures) por encima de columnas calculadas

Evita crear columnas nuevas en el modelo para cada cálculo. Las columnas calculadas consumen memoria RAM estática del archivo, mientras que las medidas en DAX se calculan al vuelo según los filtros activos, manteniendo el dashboard rápido, liviano y escalable.

Páginas de tooltips (información sobre herramientas)

Para maximizar el espacio del lienzo, configura páginas ocultas como tooltips. De esta forma, al pasar el cursor sobre una barra de «Ventas de Octubre», el usuario no solo verá un número estático, sino una mini-gráfica interactiva con el desglose por producto para ese mes específico.

Sincronización de segmentadores (Sync Slicers)

Si el reporte contiene varias pestañas, el usuario no debería tener que filtrar por «Región Norte» repetidas veces en cada página. Activar la sincronización de filtros garantiza una navegación fluida e ininterrumpida.

Marcadores (Bookmarks) para interfaces limpias

Evita sobrecargar una sola pantalla con docenas de gráficos. El uso de marcadores combinados con botones permite alternar vistas en el mismo espacio (por ejemplo, un botón para «Tendencia Mensual» y otro para «Distribución Geográfica»), transformando un reporte estático en una experiencia interactiva tipo aplicación web.

Tips generales para creación de dashboards

Cinco ideas para guiar el trabajo desde la primera pregunta hasta la entrega al usuario final.

Define el objetivo de negocio antes de conectar los datos

Un dashboard no es una galería de gráficos, es una herramienta para tomar decisiones. Los estudiantes deben preguntar siempre al inicio:

¿Qué problema resuelve esto y qué métrica define el éxito?

El trabajo duro ocurre en la preparación

La limpieza y el análisis exploratorio previo son innegociables. Si el linaje de datos es confuso, hay valores atípicos no tratados o errores de formato, el dashboard final mostrará información engañosa por muy bien diseñado que esté. La calidad visual nunca compensa una mala base de datos.

Aplica la regla de los 5 segundos

El flujo visual debe ser tan intuitivo que el usuario entienda el estado general del negocio en cinco segundos. Enseña a colocar los KPIs más críticos y resumidos en la parte superior, dejando los desgloses y tablas de detalle para la parte inferior.

Selecciona el gráfico correcto, no el más llamativo

Menos es más. Es preferible usar histogramas claros para mostrar distribuciones o diagramas de caja (boxplots) para evidenciar anomalías de forma limpia, en lugar de gráficos 3D o gráficos de pastel saturados que dificultan la comparación visual.

Diseña para generar confianza, no para mostrar código

El usuario final (o el cliente local) busca claridad técnica y valor de negocio. El dashboard debe hablar el idioma del cliente y responder a sus dudas operativas, en lugar de ser una vitrina de la complejidad técnica que el desarrollador utilizó para crearlo.
