Sección 2: arquitectura y tratamiento de datos

Esta sección tiene tres componentes y todos deben justificarse con criterio de negocio, no solo técnico.

Qué significa cada columna sobreviviente

Se documenta cada columna que quedó en la base final, con su significado y su tipo de dato: numérico, fecha o categórico.

Data Lineage: la justificación de cada decisión

Cada tratamiento se explica con una razón de negocio:

  • Nulos: por ejemplo, «Se imputaron las tiendas vacías usando la variable proxy del canal».
  • Columnas eliminadas: reducción de ruido.
  • Valores atípicos: cómo se detectaron y qué se hizo con ellos.

Cómo se unieron las tablas

Explicación técnica del cruce. Ejemplo: «Se consolidó una base maestra mediante un Left Join entre Ventas y Clima».

EDA: qué va en Python y qué en Power BI

El análisis exploratorio se hace en dos etapas y el orden importa: primero la estadística en Python, después la exploración visual en Power BI.

Obligatorio · Python

EDA estadístico: la base científica

Antes de abrir Power BI se hace la matemática pesada:

  • .describe() para ver las distribuciones.
  • Matriz de correlación numérica, para saber qué variables interactúan.
  • Boxplots de Seaborn para detectar outliers.
Bienvenido · Power BI

EDA visual: la exploración interactiva

Cuando Python confirma que los datos tienen sentido estadístico, se exporta la base maestra limpia y se conecta a Power BI.

  • Cross-filtering.
  • Gráficos rápidos de barras y líneas.
  • Objetivo: encontrar las respuestas de negocio y las tendencias que se presentarán al cliente.
import seaborn as sns
import matplotlib.pyplot as plt

df.describe()                          # distribuciones
sns.heatmap(df.corr(numeric_only=True), annot=True)   # correlaciones
sns.boxplot(data=df, x="monto")        # outliers
plt.show()

¿Por qué los outliers se corrigen en el script?

Si aparece un outlier masivo, por ejemplo una venta de un millón de dólares por un error tipográfico, la corrección debe quedar programada en el script de Python para que sea reproducible. Si se parcha en Power BI, el error sigue existiendo en la base de datos original.
