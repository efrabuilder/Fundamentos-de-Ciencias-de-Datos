Modelado dimensional para BI

Del modelo transaccional al modelo estrella y copo de nieve

¿Por qué un modelo dimensional?

Las bases de datos transaccionales están optimizadas para registrar operaciones. El modelado dimensional las reorganiza para que sea rápido y simple hacer preguntas de negocio.

Modelo transaccional (OLTP)

Optimizado para registrar (insertar, actualizar). Muchas tablas normalizadas, difícil de leer. Prioriza evitar duplicidad de datos.

Ejemplo: sistema de punto de venta.

Modelo dimensional (BI)

Optimizado para consultar y analizar. Pocas tablas, estructura clara (hechos + dimensiones). Prioriza velocidad de consulta y facilidad de uso.

Ejemplo: modelo para el dashboard de ventas.

Modelo estrella (star schema)

Una tabla de hechos central conectada directamente a las tablas de dimensión, sin niveles intermedios.

Ventaja clave: consultas simples (pocos JOIN) y fácil de entender para usuarios de negocio.

Modelo copo de nieve (snowflake schema)

Las dimensiones se normalizan en sub-tablas adicionales, reduciendo la redundancia de datos.

Ventaja: menos redundancia y datos más consistentes. Costo: más tablas y JOINs, consultas algo más lentas.

Estrella vs. copo de nieve: ¿cuál elegir?

CriterioEstrellaCopo de nieve

Integración de múltiples fuentes

Combinar datos de distintos orígenes con consistencia

Desafíos al integrar varias fuentes

Antes de combinar, hay que reconciliar cómo cada sistema representa lo mismo de forma distinta.

Claves distintas

Un mismo cliente puede tener ID diferente en el CRM y en el sistema de ventas.

Formatos distintos

Fechas, monedas o unidades registradas de forma diferente en cada sistema.

Niveles de detalle distintos

Una fuente reporta por día, otra por mes; hay que homogeneizar la granularidad.

Actualización desincronizada

Cada fuente se actualiza en momentos distintos, generando descuadres temporales.

Técnicas para combinar datos

Combinar (Merge / JOIN)

Une tablas lado a lado usando una clave en común. Amplía columnas.

Ejemplo
Ventas + Clientes por Cliente_ID

Anexar (Append / Union)

Apila tablas con la misma estructura, una debajo de otra. Amplía filas.

Ejemplo
Ventas de enero + ventas de febrero

Relaciones en el modelo

En Power BI, en lugar de fusionar todo en una tabla, se crean relaciones entre tablas separadas.

Ejemplo
Ventas relacionada con Dim_Producto

Caso práctico: ventas + inventario + CRM

Cafetería Central quiere unir tres fuentes en un solo modelo para su dashboard general — el mismo modelo estrella de arriba, ahora alimentado por tres sistemas distintos.

Sistema de punto de venta

Ventas diarias por producto y sucursal (Excel exportado).

Sistema de inventario

Existencias y costos por producto (base de datos).

CRM de clientes

Datos de clientes frecuentes y su programa de fidelidad (CSV).

Hechos_Ventas conectado a Dim_Producto (con costo e inventario) y Dim_Cliente (con datos del CRM), unificando Producto_ID y Cliente_ID como claves comunes entre las tres fuentes.

¿Por qué importa la actualización de datos?

Un dashboard hermoso con datos de la semana pasada puede llevar a decisiones equivocadas hoy.

Datos desactualizados

La gerencia decide con información que ya cambió; se pierde confianza en el reporte.

Actualización manual

Alguien exporta y sube archivos cada vez; consume tiempo y es propenso a errores.

Actualización automática

El modelo se conecta a la fuente y se refresca solo, en el horario definido.

Tipos de actualización

ManualAutomática
¿Quién la ejecuta?Una persona, cuando se acuerdaEl sistema, en el horario programado
Riesgo de errorAlto (se puede olvidar u omitir un paso)Bajo (el proceso es siempre el mismo)
EjemploExportar un Excel y subirlo a manoPower BI Service conecta y refresca solo

Actualización completa vs. incremental: la completa vuelve a cargar todos los datos desde cero; la incremental solo trae lo nuevo o lo modificado desde la última carga, y es preferible cuando el volumen de datos es grande.

¿Qué tan fácil es automatizar según la fuente?

Fuentes en la nube

SharePoint, Google Sheets, bases de datos en la nube, APIs. Se conectan directo, sin pasos manuales.

Fuentes locales (on-premises)

Bases de datos internas, archivos en un servidor de la empresa. Requieren un gateway de datos para conectarse.

Archivos sueltos

Un Excel en la computadora de alguien. Es la fuente más difícil de automatizar: primero hay que moverla a una ubicación compartida.
