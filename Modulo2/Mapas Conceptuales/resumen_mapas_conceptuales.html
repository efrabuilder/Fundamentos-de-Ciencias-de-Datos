Instalación inicial

El módulo Manejo y Preparación de Datos requiere una instalación inicial de tres pasos: primero se instala SQL Server 2025, luego SQL Server Management Studio y, por último, se reinicia el ordenador para que todo quede funcionando.

El módulo persigue un objetivo general: desarrollar habilidades para gestionar, desarrollar (preparar), mejorar y transformar bases de datos. Para lograrlo se utilizan SQL, MySQL, SQLite, Python, Power BI, Pandas y Google Colab.

Objetivos específicos

El objetivo general se detalla en seis objetivos específicos: comprender las bases de datos, aplicar consultas en SQL, evaluar la calidad de los datos, integrar múltiples fuentes, limpiar y transformar datos, y utilizar Python y Power BI.

El módulo comienza con una introducción que parte de dos conceptos. El dato representa una variable y cada usuario le da su significado; se apoya en la investigación con IoT, minería, BI y bases de datos. La información, por su parte, es un conjunto de datos que explican algo o le dan sentido, y esa información genera conocimiento, que a su vez alimenta los motores de estrategia.

Cloud y log

El módulo conecta con el tema de la nube y el registro (log). El log se registra en SQL, Excel, Oracle, Cloud, Azure, GitHub, AWS e IBM. Este tema se relaciona con la base de datos, entendida como un conjunto de datos informáticos almacenados. 2. ¿Qué es una base de datos? Historia, modelos y SGBD

La lección abarca cinco grandes temas: la historia y justificación de las bases de datos, la justificación de un modelo de datos, los sistemas de bases de datos frente a los sistemas de archivos, los tipos de bases de datos y la aplicación del álgebra relacional en modelos relacionales. El mapa desarrolla en detalle los tres primeros.

Historia y justificación de las bases de datos

Este bloque forma parte de los conceptos de dato, información y conocimiento, define el concepto de base de datos como un conjunto de datos almacenados y compartidos, y recorre su evolución histórica.

La evolución comienza con las tarjetas perforadas de Herman Hollerith, en 1884. En los años 50 siguen las cintas y tarjetas magnéticas, que sirvieron para automatizar y respaldar la información. Entre 1960 y 1970 continúa con el modelo relacional de Codd, que da origen a Oracle e IBM System R. En la década de 1980, SQL se vuelve el estándar de la industria. En los años 90 se llega a las bases de datos orientadas a objetos, como Excel y Access. La evolución incorpora además los triggers, consultas automáticas que funcionan como disparador o detonador.

Justificación de un modelo de datos

Esta justificación se centra en el modelo de datos: el conjunto de conceptos que describen la estructura, las relaciones y las restricciones de los datos. El modelo se compone de tres niveles.

Modelo conceptual. Trabaja con entidad, atributo y relación. Su ejemplo es el modelo Entidad-Relación (E-R) y los modelos semánticos. Este modelo usa una notación en la que la tabla es un rectángulo, la relación es un rombo y las variables son óvalos, y define la cardinalidad: (1,1), (1,N) y (N,M). Un ejemplo es que un cantante interpreta muchos temas, es decir, una relación 1:N.

Modelo lógico. Se divide en modelos basados en registros (jerárquico, de redes y relacional) y modelos basados en objetos (orientado a objeto).

Modelo físico. Corresponde a las tablas, columnas y claves primarias y externas.

Sistemas de bases de datos frente a sistemas de archivos

El mapa compara dos enfoques. Los sistemas de archivos son una colección de archivos de texto plano y presentan problemas: redundancia, difícil acceso, poca seguridad y limitaciones de integridad y concurrencia. Frente a ellos está el Sistema de Gestión de Bases de Datos (SGBD), que soporta DDL, DML, DCL y las propiedades ACID, y que se organiza en los niveles de abstracción ANSI/SPARC: externo, conceptual e interno.

Tipos de bases de datos y álgebra relacional

Los tipos de bases de datos y la aplicación del álgebra relacional en modelos relacionales aparecen como los dos últimos temas de la lección, sin desarrollo adicional en el mapa.

3. Cómo se guardan los datos en SQL, tipos de datos y relaciones entre tablas

Fuente: “Clase 4 - Variables SQL y Relaciones entre Tablas” (Clase_4.docx).

La clase incluye variables SQL, tipos de datos y relaciones entre tablas, y se ejemplifica con comandos SQL.

Variables SQL

Las variables se definen como espacios en memoria donde se guarda un valor temporal. Se explican con una analogía: una cajita donde se guarda un dato momentáneamente.

Tipos de datos

Los tipos de datos se clasifican en cinco grupos.

A. Texto (strings). Incluye VARCHAR(n), texto variable; CHAR(n), texto fijo; y TEXT, texto largo (obsoleto).

B. Números. Los enteros son INT (números normales), BIGINT (números grandes), SMALLINT (pequeños) y TINYINT (de 0 a 255). Los decimales son DECIMAL(p,s), de precisión exacta; NUMERIC, igual que decimal; y FLOAT, aproximado.

C. Fechas. DATE guarda solo la fecha; DATETIME, fecha y hora; TIME, solo la hora; y DATETIME2 es más preciso.

D. Booleano. Sus valores son 0 = falso y 1 = verdadero.

E. Otros importantes. IDENTITY es el auto incremento; UNIQUEIDENTIFIER es el GUID, un ID único global; y XML guarda datos en formato XML.

Relaciones entre tablas

Las relaciones se basan en claves primarias y foráneas, y se clasifican en 1:1, 1:N y N:M.

La clave primaria (PRIMARY KEY) se explica con la analogía de la cédula de identidad: es única, no se repite e identifica cada registro. Su ejemplo es CREATE TABLE Cursos (ID_Curso INT PRIMARY KEY).

La clave foránea (FOREIGN KEY) es como una referencia o enlace a otra tabla. Por ejemplo, Estudiantes guarda ID_Curso, que referencia a Cursos(ID_Curso).

La relación 1:1 (uno a uno) se explica con la analogía de que una persona tiene una sola cédula y viceversa. Un caso real de negocio es la relación entre cliente e información financiera: un cliente tiene un solo perfil de crédito. Se implementa con Clientes (PK) y Crédito (FK + UNIQUE sobre ID_Cliente).

Comandos SQL de ejemplo

Tabla con clave primaria:

CREATE TABLE Cursos (
  ID_Curso INT PRIMARY KEY,
  NombreCurso VARCHAR(50)
);

Tabla con clave foránea:

CREATE TABLE Estudiantes (
  ID INT PRIMARY KEY,
  Nombre VARCHAR(50),
  ID_Curso INT,
  FOREIGN KEY (ID_Curso)
  REFERENCES Cursos(ID_Curso)
);

Otra tabla con clave primaria:

CREATE TABLE Clientes (
  ID_Cliente INT PRIMARY KEY,
  Nombre VARCHAR(50)
);

Relación 1:1 (FK + UNIQUE):

CREATE TABLE Credito (
  ID_Credito INT PRIMARY KEY,
  ID_Cliente INT UNIQUE,
  Limite DECIMAL(10,2),
  FOREIGN KEY (ID_Cliente)
  REFERENCES Clientes(ID_Cliente)
);

4. Cómo resumir datos en SQL con COUNT, SUM, AVG, MIN, MAX, GROUP BY y HAVING

Fuente: “Clase 6 - Funciones de Agregación, GROUP BY y HAVING” (Clase_6.docx).

La clase usa las funciones de agregación (COUNT, SUM, AVG, MIN, MAX), las presenta como parte de las formas de ver datos en SQL, aplica la agrupación (GROUP BY) y el filtrado (HAVING), y aclara la diferencia clave entre WHERE y HAVING.

Formas de ver datos en SQL

Hay dos formas: el detalle, que muestra fila por fila, y el resumen, que presenta información agrupada como totales y promedios. El propósito de las funciones de agregación es pasar de detalle a resumen.

Funciones de agregación

1. COUNT() (contar). Cuenta filas. El resultado es cuántas ventas se han hecho.

SELECT COUNT(*) AS TotalVentas
FROM Ventas;

2. SUM() (sumar). Suma valores numéricos. El resultado es el total de dinero generado.

SELECT SUM(Precio * Cantidad)
AS TotalDinero
FROM Ventas;

3. AVG() (promedio). Calcula el promedio. El resultado es el precio promedio de los productos.

SELECT AVG(Precio)
AS PrecioPromedio
FROM Ventas;

4. MIN() (mínimo). Devuelve el valor más pequeño. El resultado es el producto más barato.

SELECT MIN(Precio)
AS PrecioMasBarato
FROM Ventas;

5. MAX() (máximo). Devuelve el valor más alto. El resultado es el producto más caro.

SELECT MAX(Precio)
AS PrecioMasCaro
FROM Ventas;

Agrupación y filtrado de grupos

GROUP BY (agrupar) agrupa filas con el mismo valor.

SELECT Producto,
SUM(Cantidad) AS TotalVendido
FROM Ventas
GROUP BY Producto;

HAVING (filtrar grupos) filtra los resultados después de agrupar.

SELECT Producto,
SUM(Cantidad) AS TotalVendido
FROM Ventas
GROUP BY Producto
HAVING SUM(Cantidad) > 2;

Diferencia clave: WHERE frente a HAVING

WHERE filtra filas antes de agrupar y no usa funciones agregadas. HAVING filtra después de agrupar y sí usa funciones agregadas.

Analogía de la tienda: WHERE filtra productos antes de analizar; GROUP BY hace grupos (por producto); y HAVING decide qué grupos interesan.

5. Protección de los datos: concurrencia, encriptación y blockchain

Fuente: apuntes de cuaderno, 15 de julio de 2026.

El tema incluye dos ejes: la concurrencia y la seguridad.

Concurrencia

La concurrencia busca resolver conflictos entre usuarios.

Seguridad y encriptación

La seguridad requiere la confidencialidad de los datos, que se logra con la encriptación. Esta funciona convirtiendo texto o datos en un código (ciphertext) que no se entiende sin la llave (contraseña) correcta. Tiene dos ventajas: es útil para enviar contenido privado por internet y previene la copia de información. Su riesgo es que puede ser atacada por informáticos habilidosos.

La encriptación se aplica de dos maneras: mediante algoritmos y en blockchain.

Algoritmos: AES, RSA y DES

AES (Advanced Encryption Standard) es uno de los más seguros y lo usan gobiernos y organizaciones de seguridad. Usa encriptación simétrica (key encryption) con AES-128, 192 y 256 bits.

RSA (Rivest Shamir Adleman) se usa para enviar datos online; es encriptación asimétrica con key privada propia.

DES usa 56 bits, no es muy seguro y era el método estándar de 1970. Evoluciona a 3DES, que usa tres bloques (key) de 56 bits para triple protección y es muy usado actualmente.

Blockchain

En blockchain se aplican cuatro conceptos:

Encriptación asimétrica: llave pública para encriptar y llave privada para desencriptar, sin compartir llaves.

Hashing: convierte una transacción en algo de longitud fija y verifica que no se haya modificado, como en los libros de cuentas.

Encriptación simétrica: se usa dentro de empresas y en data storage para compartir llaves.

Técnicas avanzadas: pruebas de cero conocimiento y encriptación homomórfica, que permiten transacciones confidenciales y procesos de seguridad de datos sin relevancia de líneas de información.
